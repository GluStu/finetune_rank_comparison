# Run 001: Initial LoRA Rank Comparison

## Configuration

- Model: DistilGPT-2 (`distilgpt2`)
- Dataset: WikiText-2 (`wikitext-2-raw-v1`)
- Training subset: 1,000 examples
- Validation subset: 200 examples
- Training budget: 100 steps
- Batch size: 4
- Seed: 42
- LoRA ranks: 1, 2, 4, 8, 16, 32, 64, 128
- LoRA alpha: 16
- LoRA dropout: 0.1
- LoRA target module: `c_attn`
- LoRA learning rate: 2e-4
- Full fine-tuning learning rate: 5e-5

## Hardware

- Operating system: Ubuntu 24.04.1 LTS
- CPU: AMD Ryzen 5 5600H
- GPU and VRAM: CPU-only
- Python and PyTorch versions: 3.13.3

## What Changed

Run 001 established the initial comparison between an unfine-tuned
baseline, full fine-tuning, and LoRA configurations with different
adapter ranks. The code was subsequently organized into `data.py`,
`train.py`, and `evaluate.py` to separate data preparation, training,
and evaluation.

## Findings

Across three random seeds (42, 43, and 44), the baseline validation perplexity remained 76.48, while full fine-tuning achieved a mean validation perplexity of 41.55. LoRA configurations achieved mean validation perplexities ranging from approximately 61.15 to 61.82. The best average result was obtained with LoRA rank 8, at approximately 61.23, closely followed by rank 4 at 61.14.

LoRA substantially reduced the number of trainable parameters compared with full fine-tuning. Rank 4 used 73,728 trainable parameters, while rank 8 used 147,456, compared with 81,912,576 for full fine-tuning. This represents reductions of approximately 99.91% and 99.82%, respectively. LoRA training times were also lower, taking approximately 9.2–9.9 seconds per run, compared with 14.3–14.6 seconds for full fine-tuning.

Increasing the LoRA rank did not consistently improve validation perplexity. Although higher ranks occasionally achieved competitive results for individual seeds, the differences between LoRA configurations were relatively small compared with the performance gap between LoRA and full fine-tuning.

Repeating the experiments across three seeds provides a more robust comparison than the initial single-run results. However, the findings remain preliminary because only three seeds were tested, and the baseline perplexity was identical across all runs. Overall, full fine-tuning achieved the lowest validation perplexity, while LoRA offered a substantial reduction in trainable parameters and training time, with rank 4 or rank 8 providing a reasonable balance between parameter efficiency and model performance.


## Limitations

Training time was not consistently recorded in run 001. The small
training subset and limited number of optimization steps also limit
the generalizability of the results.
