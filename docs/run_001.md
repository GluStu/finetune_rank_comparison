# Run 001: Initial LoRA Rank Comparison

## Configuration

- Model: DistilGPT-2 (`distilgpt2`)
- Dataset: WikiText-2 (`wikitext-2-raw-v1`)
- Training subset: 1,000 examples
- Validation subset: 200 examples
- Training budget: 100 steps
- Batch size: 4
- Seed: 42
- LoRA ranks: 1, 2, 4, 8, 16, 32, 64, 128
- LoRA alpha: 16
- LoRA dropout: 0.1
- LoRA target module: `c_attn`
- LoRA learning rate: 2e-4
- Full fine-tuning learning rate: 5e-5

## Hardware

- Operating system: Ubuntu 24.04.1 LTS
- CPU: AMD Ryzen 5 5600H
- GPU and VRAM: CPU-only
- Python and PyTorch versions: 3.13.3

## What Changed

Run 001 established the initial comparison between an unfine-tuned
baseline, full fine-tuning, and LoRA configurations with different
adapter ranks. The code was subsequently organized into `data.py`,
`train.py`, and `evaluate.py` to separate data preparation, training,
and evaluation.

## Findings

### 1. Full fine-tuning achieved the best validation performance
Full fine-tuning achieved a validation loss of 3.7311 and a perplexity of 41.73, improving substantially on the unfine-tuned baseline, which had a loss of 4.3371 and a perplexity of 76.48.

All LoRA configurations improved on the baseline, achieving perplexities between 61.19 and 62.54. However, none matched the performance of full fine-tuning in this experiment.

Compared with the baseline, full fine-tuning reduced perplexity by approximately 45.4%. The best LoRA configuration, rank 4, reduced perplexity by approximately 20.0%.

### 2. LoRA substantially reduced the number of trainable parameters
Full fine-tuning updated 81,912,576 parameters. LoRA updated far fewer parameters, with the total depending on the adapter rank.

Rank 1: 18,432 trainable parameters, approximately 99.98% fewer than full fine-tuning.
Rank 4: 73,728 trainable parameters, approximately 99.91% fewer than full fine-tuning.
Rank 8: 147,456 trainable parameters, approximately 99.82% fewer than full fine-tuning.
Rank 128: 2,359,296 trainable parameters, approximately 97.12% fewer than full fine-tuning.
Even at rank 128, LoRA trained fewer than 3% of the parameters updated during full fine-tuning.

### 3. Training time was lower for LoRA
Full fine-tuning took 14.57 seconds, while LoRA runs took between 9.36 and 9.75 seconds.

The fastest configuration was rank 2 at 9.36 seconds. Rank 4 took 9.50 seconds, and rank 8 took 9.45 seconds.

In this experiment, LoRA reduced measured training time by approximately 33–36% compared with full fine-tuning. These measurements apply to the recorded environment and should not be assumed to generalize to GPU-based training or other model configurations.



## Limitations

Training time was not consistently recorded in run 001. The small
training subset and limited number of optimization steps also limit
the generalizability of the results.
